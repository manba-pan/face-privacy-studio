# 下一步 AI 接入讨论稿

核对日期：2026-09-09。**仅为方案，未安装这些新模型、未接入云端，也未上传视频。** 本轮已完成的 DirectML、三档识别和短时光流属于当前功能。

建议优先做“框一次，持续跟住头部”，其次做“AI 帮忙挑出可疑片段”。前者直接减少手动补码，后者减少复查时间。用大模型逐帧替代全部人脸检测，当前不作为首选。

## 为什么“头部跟踪”更对症

转头只剩后脑时，画面里可能已经没有传统检测器所定义的“脸”。持续遮挡需要记住先前选中的目标，并处理消失、重现、遮挡和镜头切换。把马赛克调大或降低检测阈值，只能解决部分覆盖问题，还可能把衣服识别成脸。

SAM 3 官方支持文字或点、框、掩码提示下的图像和视频分割。仓库在 2026-03-27 发布 SAM 3.1，重点包含共享内存的多目标跟踪改进。我们可以先试“框住头部→传播几秒→用户修正→再继续”，不要直接让它自动认定整部视频里谁是谁。官方安装要求包含 CUDA GPU；RX 9070 XT 不能直接照着 CUDA 步骤使用。Windows / AMD 的导出、算子支持和速度需要独立验证，这一轮 DirectML 跑通 YuNet，不代表 SAM 已兼容。[SAM 3 官方仓库](https://github.com/facebookresearch/sam3)、[SAM 3.1 更新说明](https://github.com/facebookresearch/sam3/blob/main/RELEASE_SAM3p1.md)。

SAM 2 的代码和模型采用 Apache 2.0，官方在 Windows 上建议 WSL；这也说明它距离普通用户双击 EXE 的体验还有工程工作。可以用它作为较成熟的对照组，再决定是否采用更新的 SAM 3.1；后者使用自己的 SAM License，需逐项核对实际分发条件。[SAM 2 官方说明](https://github.com/facebookresearch/sam2)、[SAM 3 许可](https://github.com/facebookresearch/sam3/blob/main/LICENSE)。

## AI 复查怎么避免变成另一种等待

只在用户点击后运行；优先检查“数量突然减少、跟踪补偿、边缘目标、转场”的短窗口，再加入均匀抽样，不能只看已有检测框，否则会遗漏检测器从未找到的人。展示时间码、截图和简短原因，用户可以接受建议或忽略。原视频的每帧遮挡仍由可验证的几何渲染完成。

Qwen3.5-9B 官方模型卡提供视觉 / 视频理解说明并标记 Apache 2.0，可作为本地复查助手的候选。它是否擅长判断漏码、使用哪种更小模型、量化是否影响结果，以及在这张 AMD 显卡上的后端兼容性，都需要实验；官方通用视频理解分数不能当作本工具的漏码检出率。[Qwen 官方模型卡](https://huggingface.co/Qwen/Qwen3.5-9B)。

默认仍全部本地。若以后增加云端方案，应单独显示将发送哪些画面、预计费用和删除策略，让用户主动选择。当前方案不预设任何云端服务，也不产生 API 费用。

## 更强检测器先看权重，再看榜单

InsightFace 官方区分代码与模型许可：代码允许的用途不代表其提供的预训练模型也允许，模型说明包含非商业研究限制。本工具允许用户接剪辑单和制作商业视频，因此不能把现成权重直接塞进默认安装包。可选方向是取得适用授权、找到许可明确的替代权重，或用获授权数据训练；还要测真实侧脸和半脸，不能仅凭模型名称断言更准确。[InsightFace 官方许可说明](https://github.com/deepinsight/insightface#license)。

## 一版可验收的小实验

1. 取 10～20 段获授权的短视频，包含转头、被挡、脸出画、多人交叉和转场；人工标注需要遮住的范围。私人素材留在本地。
2. 对比当前细致档、点选头部跟踪、AI 复查建议。记录漏码帧数、最长连续露出时间、误遮挡面积、每分钟需要人工修正几次、处理耗时及峰值显存。采用逐帧检查而非“检测框总数”评价准确性。
3. 先证明短片有实际收益，再设计按需下载的模型包与独立后台进程。检测到模型不适配时，普通打码功能仍可使用；后台取消、重启、缓存和版本分别管理。

第一版范围建议收在：**框选一个头部、传播一个短片段、能修正、能撤回**。人物选择、车牌、屏幕文字等可以之后复用这套目标与时间段交互；复杂多轨剪辑暂不混入这个实验。
